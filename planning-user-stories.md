# Organización de historias de usuario

**Fuente:** [Organización de Historias de Usuario](https://app.notion.com/p/3b0d6ab9f4dd81f0b894cc5c5c4ba202)  
**ID Notion:** `3b0d6ab9-f4dd-81f0-b894-cc5c5c4ba202`

La jerarquía de planificación es **Release → Epic → User Story**. La historia de usuario es la unidad mínima; no se crean Task o Subtask como práctica normal.

Cada historia incluye título, descripción, objetivo, épica, release objetivo, prioridad, estado, dependencias y criterios de aceptación. Estos criterios describen comportamiento esperado, no solución técnica, y deben ser verificables y objetivos cuando sea posible.

La IA de desarrollo analiza la historia, diseña la solución, identifica cambios, genera un plan y ejecuta conforme a las convenciones definidas en [[project-foundation]] y el flujo obligatorio en [[development-workflow]]. Solo se documentan tareas técnicas cuando aportan valor real: migraciones complejas, refactorizaciones grandes, integraciones externas, cambios con secuencia necesaria, spikes, procedimientos operativos o actividades manuales no inferibles.
